# Доменная документация

Правила использования доменной документации репозитория инженерными навыками при изучении кодовой базы.

## Что прочитать перед изучением кодовой базы

- **`CONTEXT.md`** в корне репозитория или
- **`CONTEXT-MAP.md`** в корне репозитория, если он существует. Этот файл указывает на отдельный `CONTEXT.md` для каждого контекста. Прочитайте каждый файл, относящийся к текущей задаче.
- **`docs/adr/`** — прочитайте ADR, относящиеся к области предстоящей работы. В многоконтекстных репозиториях также проверяйте `src/<context>/docs/adr/` на наличие решений конкретного контекста.

Если каких-либо из этих файлов не существует, **продолжайте работу без уведомления пользователя**. Не отмечайте их отсутствие и не предлагайте создать их заранее. Навык `/domain-modeling`, вызываемый через `/grill-with-docs` и `/improve-codebase-architecture`, создаёт эти файлы по мере необходимости, когда действительно определяются термины или принимаются решения.

## Структура файлов

Одноконтекстный репозиторий — вариант для большинства проектов:

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

Многоконтекстный репозиторий, обозначаемый наличием `CONTEXT-MAP.md` в корне:

```text
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← общесистемные решения
└── src/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← решения конкретного контекста
    └── billing/
        ├── CONTEXT.md
        └── docs/adr/
```

## Используйте терминологию глоссария

Когда в результате работы упоминается доменное понятие — в названии задачи, предложении по рефакторингу, гипотезе или названии теста — используйте термин из `CONTEXT.md`. Не заменяйте его синонимами, которые глоссарий явно не рекомендует.

Если нужного понятия ещё нет в глоссарии, это важный сигнал: либо используется термин, не принятый в проекте, и его следует пересмотреть, либо в модели действительно есть пробел, который стоит отметить для `/domain-modeling`.

## Отмечайте противоречия с ADR

Если результат работы противоречит существующему ADR, укажите это явно, а не заменяйте решение молча:
